### [甲骨文发布 Java SE 高危漏洞安全警报](https://www.oracle.com/security-alerts/alert-cve-2026-91403.html) ⭐️ 8.0/10

甲骨文公司发布安全警报，披露 Java SE 产品中存在编号为 CVE-2026-91403 的严重漏洞，CVSS 评分为 9.1。该漏洞位于 JSSE 组件，攻击者无需身份验证即可通过网络远程利用，可能严重破坏数据的机密性与完整性。受影响版本包括 Java SE 8u511、11.0.33、17.0.21、21.0.13、25.0.5、27.0.1 以及 GraalVM 的多个版本。甲骨文已同步推出修复补丁，并呼吁用户尽快升级至受支持版本，以防范潜在的网络攻击风险。

telegram · zaihuapd · 10月22日 20:30

**「背景」** JSSE（Java Secure Socket Extension）是 Java 平台提供 TLS/SSL 与安全套接字通信的标准组件，广泛用于建立加密网络连接。根据外部漏洞库记录，CVE-2026-91403 属于 CWE-295（证书验证不当）类弱点，攻击者可通过向相关 API 提供数据的 Web 服务等途径触发，也可能影响加载并运行不可信代码的沙箱化 Java Web Start 应用或 Applet 部署场景。

**「影响」** 使用受影响 Java SE 或 GraalVM 版本、且依赖 JSSE 进行 TLS 通信的用户和开发者，需尽快升级至最新 Java 版本或按甲骨文建议应用缓解措施，以防范无需认证的远程攻击者篡改关键数据。

### [333 个 Tor 出口节点被植入 Ebury 后门后下线](https://kaba.cx/posts/20261020_Tor/) ⭐️ 8.0/10

一名 Tor 运营者用脚本扫描了约 3000 个出口中继，发现其中 333 个（约占 10%）被植入 Ebury 后门。这些节点可将 22 端口的 SSH 连接劫持到 12 台拦截服务器并窃取凭据。10 月 4 日，这些节点被标记为 BadExit，次日全部下线。攻击者早在今年 8 月就已入侵这些服务器，并屏蔽部分端口以专门收集未加密邮件流量；入侵途径目前尚无定论。

telegram · zaihuapd · 10月22日 22:52

**「背景」** Ebury 是一个自 2009 年起活跃的 OpenSSH 后门与凭据窃取程序，主要通过篡改 OpenSSH 调用的共享库（.so 文件）植入，用于维持对 Linux 服务器的访问、窃取认证信息并重定向流量。据 ESET 2024 年的研究，该僵尸网络仍在增长，曾被用于部署额外恶意软件、代理垃圾邮件流量以及实施中间人攻击。此次事件中，攻击者正是利用 Ebury 劫持 Tor 出口节点的 SSH 流量。

**「影响」** 依赖 Tor 出口节点进行 SSH 或未加密邮件传输的用户，其凭据可能已被劫持至 12 台拦截服务器；这些节点被标记为 BadExit 并下线后，相关流量不再经由这批中继出口。不过入侵途径尚未确定，其他出口节点是否同样受影响仍缺乏独立验证。

### [米哈游联合清华开源 GameScaling 游戏操作模型](https://arxiv.org/abs/2610.28698v1) ⭐️ 7.0/10

米哈游崩坏 AI 团队联合清华大学等机构发布 GameScaling，基于 Qwen3.5 视觉语言模型进行键鼠操作继续预训练，模型规模覆盖 0.8B 至 27B，每次输出未来 200 毫秒的键鼠动作。配套论文使用 120 组训练配置考察数据量、多样性与模型规模的影响，结论是数据越多同源表现越好，多样性有助于迁移到相近游戏，但对差异较大的游戏世界提升有限。团队以 Apache-2.0 协议开源了八个检查点与推理客户端，但不包含训练代码。

telegram · zaihuapd · 10月22日 19:32

**「背景」** GameScaling 建立在 Qwen3.5 视觉语言模型之上，通过在键鼠游戏操作数据上继续预训练，使模型能够直接根据画面预测操作。其项目主页指出，虚拟世界与物理环境不同：每款游戏都有各自的视觉风格、动态规律、控制方式和目标，因此难以像现实世界那样依赖共享的物理法则实现经验迁移。该工作正是围绕数据量、数据多样性与模型容量对具身智能体学习的影响展开研究。

**「影响」** 对游戏 AI 与具身操作研究者而言，Apache-2.0 的八个检查点和推理客户端可直接用于复现与二次开发，但缺少训练代码意味着难以完整复刻其数据缩放实验。论文结论也表明，这类模型向差异较大的游戏迁移时提升有限，跨游戏泛化仍是主要限制。

Arc 官方宣布将于 2026 年 12 月 22 日停止服务，团队将转向 AI 浏览器 Dia。官方给出的理由是，要为会员提供一流的安全保障，而在 AI 时代，维护浏览器安全所需的工作量不断增加。迁移方面，密码、书签、扩展、历史记录以及 Spaces、文件夹、标签组均可完整导入 Dia。官方还称，Dia 在稳定性、速度和安全性上已超过 Arc，常用功能免费，AI 为可选项；这些关于 Dia 优势的说法目前均为厂商自述，尚未经过独立验证。

**「背景」** Arc 是 The Browser Company 推出的基于 Chromium 的浏览器，以独特的设计和 Spaces、标签组等功能受到部分重度用户青睐。该公司随后将重心转向 AI 优先的浏览器 Dia，并于 2025 年被 Atlassian 以 6.1 亿美元收购。此次停服公告于 2026 年 10 月 22 日发布，桌面用户约有两个月时间迁移数据。

**「影响」** Arc 现有用户需在 2026 年 12 月 22 日前完成向 Dia 的迁移，密码、书签、扩展、历史记录及 Spaces、文件夹、标签组可完整导入；但外部评测指出 Dia 截至 2026 年 6 月尚未提供 Arc 原有的 Spaces 和 Cmd+T 命令栏，习惯这些工作流的用户可能面临功能落差。
