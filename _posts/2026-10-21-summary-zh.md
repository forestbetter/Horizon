### [OpenAI 新模型提升 COBOL 等低资源语言能力](https://openai.com/index/low-resource-programming-languages/) ⭐️ 8.0/10

一则 Telegram 帖子称，OpenAI 最新模型显著提升了 COBOL、Fortran 和 Visual Basic 等低资源编程语言的开发与迁移能力。在“用 20 种语言从零构建 SQLite 引擎”的测试中，GPT-6 Astra 的平均通过率从 GPT-5.6 Sol 的 26.8% 升至 87.4%，低成本模型 GPT-6 Luna 达到 40.3%，API 成本下降 78%。在将老旧 COBOL 代码迁移至现代语言的测试中，GPT-6.1 Sol 在低推理强度下准确率从 5.4% 升至 86.6%、成本降低 39%，高推理强度下准确率达 97.9%。帖子还称相关评测集已在 GitHub 开源。上述模型名称与数字均来自该 Telegram 摘要，尚未经独立核实。

telegram · zaihuapd · 10月20日 22:24

**「背景」** 低资源编程语言指 COBOL、Fortran、Visual Basic 等在公开代码语料中占比很小、因而大模型训练数据稀缺的语言，模型在这些语言上的生成与迁移能力通常明显弱于 Python 等主流语言。COBOL 尤其特殊：它长期支撑银行、保险和政府的大型机系统，存量代码庞大，但掌握它的开发者持续减少，把旧代码迁移到现代语言因此成为长期存在的工程难题。据 OpenAI 页面，GPT-6 Astra 与 GPT-6 Sol、Luna 采用相近的训练方法，后两者定位为更快、更便宜的版本。

**「影响」** 若这些数据成立，依赖 COBOL 等低资源语言的金融机构和遗留系统维护团队可能获得显著更高的自动化迁移准确率，并在低推理强度下大幅降低成本；但迁移评测集并未公开，实际可复现性仍待验证。

### [Google 开源 TorchTPU，TPU 成为 PyTorch 原生后端](https://cloud.google.com/blog/topics/ai-infrastructure/torchtpu-is-now-open-source-run-native-pytorch-on-tpus) ⭐️ 8.0/10

Google Cloud 宣布，与 Meta 的 PyTorch 团队共同开发的 TorchTPU 已在 GitHub 开源。TPU 由此成为与 GPU、CPU 并列的 PyTorch 原生选项，现有代码几乎无需改动即可运行。vLLM、SGLang、llm-d、TorchTitan 等推理与训练框架已接入，Hugging Face Transformers v5 可直接把模型部署到 TPU。此举降低了在 TPU 上运行 PyTorch 工作负载的迁移成本，被视为对 NVIDIA 主导的 AI 硬件与软件生态的挑战。

telegram · zaihuapd · 10月21日 08:47

**「背景」** PyTorch 由 Meta 主导开发，长期以 GPU 和 CPU 为主要执行后端，而 Google 的 TPU 此前主要通过 JAX 或 TensorFlow 生态使用，PyTorch 模型迁移到 TPU 通常需要额外适配。TorchTPU 是 Google 与 Meta PyTorch 团队合作推出的原生 PyTorch 后端，提供自定义 ATen 内核与编译缓存，支持 eager 模式调试并通过 torch.compile 优化 TPU 利用率。

**「影响」** 对现有 PyTorch 用户而言，TorchTPU 使 TPU 成为无需大幅改动的原生后端，vLLM、SGLang、llm-d、TorchTitan 及 Hugging Face Transformers v5 的接入降低了将训练与推理迁移到 TPU 的门槛。不过其分布式实现采用每设备单进程模型，且单个 TPU 设备只能由一个用户态进程访问，这会影响多进程部署方式的设计。

### [Uber 用 AI 系统 AutoClean 清理技术债](https://www.uber.com/us/en/blog/ai-code-cleanup/) ⭐️ 7.0/10

Uber 发布博客，介绍其 AI 系统 AutoClean 如何自动清理生产代码中过期的 feature flag 等遗留技术债。该系统在 Uber 的多个 monorepo 中持续运行，过去几年已清理超过 16000 个 flag 和 100 多万行代码。流程分三步：先用 AI agent 结合确定性代码变换工具 PolyglotPiranha 重写代码，再修复 CI 失败并反复验证，最后经静态检查和多 agent 校验系统 CodeCourt 审核后才交由人类工程师最终评审。这样评审者只需判断是否该移除某个 flag，不必检查机械性的正确性问题。上述规模数据来自 Uber 自述，并非独立研究结果。

telegram · zaihuapd · 10月21日 14:45

**「背景」** Feature flag（功能开关）用于在不重新部署的情况下控制功能是否生效，但功能上线后长期未清理的过期 flag 会形成技术债，增加代码复杂度与维护成本。Uber 此前已开源 PolyglotPiranha，该工具以 flag 名称和期望行为为输入，结合配置文件中声明的 flag API 列表，自动重构与过期 flag 相关的代码，并支持多种编程语言。AutoClean 正是在这一确定性变换工具之上叠加 AI agent 与 CI 修复、多 agent 审核流程，以扩大清理规模。

**「影响」** 对维护大型 monorepo 的工程团队而言，这一案例表明 AI 可承担过期 feature flag 清理中的机械性改写与验证工作，把人工评审聚焦到是否移除的业务判断上。
