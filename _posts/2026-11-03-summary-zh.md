### [Linux 内核 IPv4 TCP 高危释放后使用漏洞预警](https://telegram.me/zaihuapd/44866) ⭐️ 8.0/10

Telegram 频道“科技圈·茶馆”发布提醒，称 Linux 内核 IPv4 TCP 存在高危释放后使用漏洞（CVE-2026-98432），攻击者可自网络侧利用，无需认证，也无需用户交互。该提醒称 Anthropic 已公布针对 MPTCP 监听端口的远程代码执行（RCE）利用示例，并强调漏洞并非只影响 MPTCP 场景。Go 官方安全团队提示，自 Go 1.24 起 Linux 上的 listen socket 默认启用 MPTCP，因此用 Go 编写的服务默认处于暴露状态；即使没有 MPTCP 监听，也可能受到同类攻击。该帖内容简短，未给出修复版本、补丁状态或厂商公告链接，建议有服务器的用户关注内核更新并核实官方修复信息。

telegram · zaihuapd · 11月3日 10:37

**「背景」** 该漏洞位于 Linux 内核 IPv4 网络子系统的 TCP 连接请求处理路径，属于释放后使用（use-after-free）类型的内存安全问题。据 AWS 安全公告，受影响的是 4.4 及之后的内核版本；攻击者可在特定条件下向受影响的监听端口发送携带 IP 选项的构造 IPv4 TCP 报文，从而触发该问题。Red Hat 的安全公告将其描述为 TCP 连接请求处理过程中的竞态条件，远程未认证攻击者可借此实现远程代码执行。

**「影响」** 使用 Go 1.24 及以上版本在 Linux 上运行监听服务的开发者，默认会启用 MPTCP，因此可能直接暴露在该漏洞的攻击面下；而按程序逐个关闭 MPTCP 的缓解方式并不可靠，只要漏掉一个监听端口，系统仍会处于风险之中。

俄罗斯总统普京签署总统令，要求俄罗斯境内非国有数据中心预留 10%的场地和计算能力，供政府在必要时调用，以保障国内信息技术基础设施及信息资源正常运行。根据该总统令，俄罗斯数字发展部须对全国私营数据中心的可用场地和计算能力进行清查。政府将成立专门委员会，有权要求数据中心释放预留资源，运营商须在接到通知后 24 小时内提供使用权限。此外，经俄罗斯联邦安全局（FSB）批准，政府还可临时调用位于境外的数据中心资源。
